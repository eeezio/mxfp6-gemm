5. Full-table sweep — every benchmark_results.md shape our kernel can run
================================================================================

Same machine/date/image as above. 36 shapes (all rows with N % 256 == 0); one pass of
`test_gemm 2048 N K` each, then CK on the same list. The 14 rows with N % 256 != 0 are
omitted: the launch grid is dim3(M/MT, N/NT) with integer division, so those shapes are
either not launched at all (N=1, N=128 -> floor(N/256)=0) or leave floor(N/256)*256..N
uncomputed (N=3490 / 12672 / 102272).

CK refuses K % 256 != 0 ("Can't support K that is not a multiple of KPerBlock without
padding!" / "K must be multiple of ScaleGranularityK"), which is why 14 of the CK lines
below are blank. CK also has no config sweep in this binary (-persistent=1 fails on these
shapes), and at N <= 1024 its single config lands at 0.33-0.54x of the tuned CK numbers
the 2026-06 harness recorded -- so only the N >= 4096 CK numbers are used in the table.
